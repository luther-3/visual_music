  - 备注：当前会话下 ffmpeg 仍未被 PATH 识别（verify 输出 WARN），MP3 支持待终端 PATH 生效后复检

- 第 1 步：config.py 已完成
  - 频段范围已对齐：`HIGH_FREQ_RANGE=(4000, 11025)`
  - 粒子上限已对齐：`MAX_PARTICLES=3000`
  - 已补齐：`NORMALIZATION_WINDOW_SIZE=86`、`TRAIL_ALPHA=40`、`SHOW_INFO=True`
  - 中频粒子配置已补充 `orbit_centers`
  - 验证通过：`python -c "import config; print(config.WINDOW_WIDTH)"` 输出 `1280`

- 第 2 步：utils.py 已完成
  - 完成函数：`interpolate_color()`、`map_value()`、`freq_to_bin()`、`normalize_energy()`
  - `normalize_energy` 已按规范改为：`np.clip(energy / local_max, 0, 1) if local_max > 0 else 0`
  - `map_value` 增加输入范围保护：`in_min == in_max` 时返回 `out_min`
  - 验证通过：
    - `python -c "from utils import interpolate_color; print(interpolate_color((0,0,0),(255,255,255),0.5))"` 输出 `(127, 127, 127)`
    - `python -c "from utils import map_value, freq_to_bin, normalize_energy; print(round(map_value(5,0,10,0,100),2), freq_to_bin(4000,22050,2048), normalize_energy(3,6))"` 输出 `50.0 371 0.5`

- 第 3 步：audio_processor.py 已完成
  - 新增 `AudioData` 数据容器：`audio_samples`、`sample_rate`、`duration`、`n_frames`、三频段对数能量、`phase`
  - 实现 `AudioData.get_normalized_energy(frame_index, window_size=86)`：滑动窗口局部最大值归一化，返回 `(low, mid, high)` 三个 `[0,1]` 浮点数
  - 实现 `AudioProcessor.load(file_path)`：音频加载、STFT、三频段能量计算、`log10(energy+1)` 对数映射、异常捕获返回 `None`
  - 实现 `_calculate_band_energy(magnitude, freq_range)`：按 `freq_to_bin` 频段切片并 `axis=0` 求和
  - 兼容性说明：当前环境中 `librosa.stft` 调用阻塞，已改为参数等价的 `scipy.signal.stft` 完成 STFT（`nperseg=2048`、`noverlap=1536`、`window='hann'`、`nfft=2048`）
  - 验证通过（使用临时 `test.wav`）：
    - `data.n_frames` 输出 `40`（正整数）
    - `data.get_normalized_energy(0)` 输出 `(0.8253040054726488, 0.9999946231211169, 0.8866305083766464)`（均在 `[0,1]`）

- 第 4 步：particle_system.py 已完成
  - 新增 `Particle` 类：实现低/中/高频三种 `update()` 逻辑、`is_alive()`、`is_out_of_bounds()`
  - 新增 `ParticleEmitter` 类：支持按能量发射粒子、分类型初始化参数、更新并清理越界/死亡粒子
  - 新增 `ParticleSystem` 类：三发射器组合、`display_mode` 切换、`MAX_PARTICLES` 总量限制、清空接口
  - 关键行为对齐规范：
    - 低频：中心爆发径向运动
    - 中频：按 `orbit_centers` 环绕运动
    - 高频：随机游走并方向扰动
  - 验证通过：
    - `python -c "from particle_system import ParticleSystem; ps=ParticleSystem(); ps.update(0.8,0.5,0.3); print(len(ps.get_particles_to_render()))"` 输出 `270`
    - `python -c "from particle_system import ParticleSystem; ps=ParticleSystem(); ps.set_display_mode('low'); ps.update(1.0,1.0,1.0); print(len(ps.low_emitter.particles), len(ps.mid_emitter.particles), len(ps.high_emitter.particles), len(ps.get_particles_to_render()))"` 输出 `100 179 300 100`

- 第 5 步：visualizer.py 已完成
  - 新增 `Visualizer` 类：
    - `__init__()`：初始化 `pygame`、窗口、`mixer`、`ParticleSystem`、状态变量、时钟与字体
    - `run(audio_data, audio_file_path)`：加载并播放音频，执行主循环
    - `_handle_events()`：支持 `ESC` 退出、`SPACE` 暂停/继续、`1/2/3/A` 显示模式切换
    - `_get_current_frame()`：按 `get_pos()` 转换帧索引并做边界保护
    - `_render()`：拖尾背景 + 粒子渲染 + 信息层（FPS/时间/模式）
    - `cleanup()`：`pygame.mixer.music.stop()` 和 `pygame.quit()`
  - 验证通过（当前环境使用 SDL dummy 驱动做无界面验证）：
    - 初始化验证输出：`init_ok all False`
    - 渲染路径验证输出：`render_ok 270`

- 第 6 步：main.py 已完成
  - 新增 `select_audio_file()`：使用 `tkinter.filedialog` 弹出系统文件选择框，支持 `mp3/wav/flac/ogg`
  - 新增 `main()` 主循环：
    - 未选择文件：输出“未选择文件，程序退出。”并结束
    - 音频加载失败：`continue` 返回文件选择界面
    - 音频加载成功：创建 `Visualizer`，调用 `run()`，结束后 `cleanup()`
  - 增加异常安全：`Visualizer.run()` 使用 `try/finally` 保证总能执行 `cleanup()`
  - 兼容性更新：README 运行方式改为 `python main.py`（由对话框选文件）
  - 验证通过（命令级流程打桩验证）：
    - 取消选择路径：输出 `未选择文件，程序退出。`
    - 加载失败路径：可回到选择并最终退出
    - 加载成功路径：成功调用 `viz_run` 与 `viz_cleanup`

已知风险和注意事项
----------------------------------------------------------------

- tkinter 和 Pygame 窗口不能同时显示，切换前必须 root.destroy()
- Pygame per-pixel alpha 渲染需要 pygame.SRCALPHA 标志
- MP3 支持需要 FFmpeg，先用 WAV 测试
- pygame.mixer.music.get_pos() 暂停后继续计时，暂停逻辑需特别处理
- 粒子总数超过 3000 时停止发射新粒子
